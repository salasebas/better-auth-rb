`better_auth-redis-storage` provides an official Redis-backed secondary storage implementation for RubyAuth. It tracks the server-side behavior of upstream `@better-auth/redis-storage` pinned at Better Auth `v1.6.23`, while using Ruby naming and the Ruby `redis` client.

## Installation

Add the storage gem and Redis client to your Gemfile:

```ruby
gem "better_auth-redis-storage"
gem "redis"
```

Then install your bundle:

```bash
bundle install
```

## Basic Usage

Require the package before configuring auth:

```ruby title="config/better_auth.rb"
require "redis"
require "better_auth/redis_storage"

redis = Redis.new(url: ENV.fetch("REDIS_URL"))

auth = BetterAuth.auth(
  secret: ENV.fetch("BETTER_AUTH_SECRET"),
  database: :memory,
  secondary_storage: BetterAuth.redis_storage(client: redis)
)
```

The canonical Ruby class form is also available:

```ruby
storage = BetterAuth::RedisStorage.new(client: redis)
```

For upstream-shaped call sites, `BetterAuth.redisStorage(client: redis)` and the `keyPrefix:` keyword are also accepted.

## Configuration

```ruby
storage = BetterAuth::RedisStorage.new(
  client: redis,
  key_prefix: "better-auth:",
  scan_count: BetterAuth::RedisStorage::SCAN_DEFAULT_COUNT,
  atomic_clear: false
)
```

### `client`

The Redis client must respond to `get`, `set` (including `nx:` and optional `ex:` keyword options), `setex`, `del`, `eval`, and `scan`. It should also respond to `keys` only when `scan_count: nil` is configured. Atomic clear installs and rotates its generation marker with single-key Lua scripts through `eval`; it does not require `incr`.

The storage exposes `get_and_delete` (`getAndDelete`) for atomic single-use
consumption. It prefers Redis `GETDEL` and falls back to Lua for Redis versions
before 6.2. `increment(key, ttl)` atomically returns the post-increment value
and sets expiry only when it creates the counter, so later increments do not
extend the fixed window. `set_if_absent(key, value, ttl)` (`setIfAbsent`) uses
Redis `SET NX` with optional expiry and returns `true` only to the caller that
created the key, providing a cross-process first-writer-wins reservation gate.

### `key_prefix`

`key_prefix` defaults to `"better-auth:"`. Passing `nil` falls back to the default. Any other value, including the empty string, is honored verbatim.

<Callout type="warning">
  Passing `key_prefix: ""` puts Better Auth keys at the root of the selected Redis logical namespace. `list_keys` and `clear` then match `*`, so `clear` deletes every key in that Redis database. Use an application-specific prefix unless the Redis database is fully dedicated to Better Auth.
</Callout>

### `scan_count`

`scan_count` defaults to `BetterAuth::RedisStorage::SCAN_DEFAULT_COUNT` and uses Redis `SCAN` for `list_keys` and `clear`.

```ruby
storage = BetterAuth::RedisStorage.new(client: redis, scan_count: 500)
```

Set `scan_count: nil` for exact legacy upstream behavior using blocking `KEYS "#{key_prefix}*"`. Use that only for small or dedicated Redis databases because `KEYS` can block Redis while it walks the keyspace.

```ruby
storage = BetterAuth::RedisStorage.new(client: redis, scan_count: nil)
```

### `atomic_clear`

`atomic_clear` is a Ruby-only opt-in for applications that need `clear` to be logically atomic under concurrent writers.

```ruby
storage = BetterAuth::RedisStorage.new(
  client: redis,
  scan_count: 500,
  atomic_clear: true
)
```

When enabled, data keys are stored under an opaque, 256-bit generation prefix such as `better-auth:v4f7c...:<key>`. A single-key Lua script atomically installs a fresh generation when the marker is missing or malformed, so concurrent processes converge on one marker instead of falling back to an older namespace. Calling `clear` atomically replaces the marker with a fresh token, moving new reads and writes to the new generation before best-effort cleanup of the previous generation. Positive decimal generation markers written by earlier releases remain valid, so existing versioned data stays readable; the next `clear` rotates a legacy marker to an opaque token without using `INCR`. Redis errors before marker replacement leave the current generation unchanged. If replacement commits but its reply is lost, or if physical cleanup later fails, the error propagates while the advanced marker keeps old keys logically hidden. This boundary assumes Redis preserves the committed marker and does not cover restoring an older Redis snapshot or an equivalent storage rollback. In Redis Cluster, each generation script touches only the marker key, but scanning and physical deletion retain the adapter's node-coverage and hash-slot constraints.

## When to Use It

Use Redis Storage when you want RubyAuth secondary storage backed by Redis for short-lived auth data, session payloads, active-session indexes, verification values, rate limiting counters, or API key storage.

## Verification

The package includes unit coverage and Redis integration tests. The normal test suite skips real Redis unless explicitly enabled; the package README documents `REDIS_INTEGRATION=1 REDIS_URL=redis://localhost:6379/15 bundle exec rake test:integration` for maintainers who need to run the integration suite.
